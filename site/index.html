local-first · agent runtime assurance · policy-as-code

AI capability is not AI authority.

A local-first agent runtime assurance and governance plane that fronts whatever serves your models — an enterprise LLM platform, vLLM/Ollama, or local MLX — and mediates every call with policy-as-code identity, an enforced L0–L6 autonomy ceiling, per-tool and per-skill grants, egress guardrails, and a structured decision audit. Execution needs explicit owner-granted authority, and what was authorized and what then happened is recorded as a signed, durably stored evidence chain an independent verifier re-derives — enforced in code, before any token is generated, not asserted in a README.

01 · A goal, in plain language

You type an objective. Nothing is authorized yet.

The Governed Chat Console is one static file behind a strict default-src 'none' CSP. It stores no token, holds no authority, and cannot approve anything. Every line that follows is a real gateway decision on the wire — not a narrated transcript.

02 · Planning, capped at L1

Hermes reads the enforced directory and proposes — it cannot execute.

The planner makes one governed model call inside its L1 ceiling, then discovers a peer that advertises code.apply at the lowest sufficient level. It never names the executor up front and never grants itself anything. The proposal is a request, not a decision.

03 · The agent cannot approve itself

Same wire, planner identity, real 403.

Handing the planner's own token to the approval box returns owner_required from the gateway — the single most important boundary in the product. The run stays frozen and the proposal stays open, so a human can still decide.

04 · A human grants bounded authority

Owner-gated, hash-bound, single-use.

The approval binds to this run's canonical plan hash and expires. Editing the goal box afterwards cannot move it: execute recomputes the hash server-side and refuses on drift. OpenCode then applies in a confined sandbox and sub-delegates verification.

05 · Signed evidence, then an independent verdict

Three signed records, one durable chain, verified fail-closed.

approval_decided ← execute_validated ← apply_result, each signed by its own emitter with its own key, linked by evidence references. OpenClaw verifies the chain and the linkage before it will return PASS — an unsigned self-attested report alone cannot produce one. HMAC here is tamper-evident, not non-repudiable.

06 · Withhold authority

No approval, no apply. The refusal is the feature.

Running the same frozen plan without an approval returns a governed refusal (approval_missing) — an HTTP 200 outcome, not an error. Nothing was applied, and the attempt is in the audit.

07 · Abuse the same wire deliberately

Over-ceiling delegation and an ungranted skill: both refused.

One click asks the executor to run above its enforced ceiling and routes a skill the planner was never granted. Both come back refused with their exact audit codes (autonomy_amplification, skill_not_delegable).

08 · Switch to inspection

The Governance Console is the same runtime, seen from the outside.

Chat is where you operate; the console is where you inspect. It authenticates independently — no token is shared, persisted, or passed between the two pages. Deny-by-default means the red in the enforcement ratio is the plane doing its job.

09 · The run you just watched, as evidence

Every hop of the chat run is already in the audit.

The self-approval denial, the owner's approval, both delegations, the sandbox result and the withheld-authority refusal — recorded with principal, path, reason code and status. This is the same stream a SIEM consumes.

10 · Prompts do not raise ceilings

Declare L6 from a capped identity — refused before any model loads.

The probe lab sends real requests designed to be refused. Autonomy is a property of the identity in policy, not a field the caller may assert.

11 · Blast radius, declared

Every tool carries an honest autonomy floor.

Holding a tool is not permission to use it. A principal below a tool's floor is refused even when the tool is explicitly granted — granted is not permitted.

12 · Capability is not authority

The model can propose anything. It can change nothing without you.

A capable planner, a confined executor, an independent verifier, and a signed durable record of exactly who authorized what. Backed by 1195 tests on two platforms and 23 adversarial evals that fail CI on regression.

Orchestration

Three agents, one closed loop

Each component authenticates as its own principal with its own autonomy ceiling — no shared "god" identity. A model may reason about anything; what executes is decided and recorded by the governance plane.

plan → act → verify → record → re-plan

🧭 Hermes L1 · suggest

A stateful planner. Delegates one planning cycle to the gateway, records the plan to memory — and is denied 403 if it asks to operate above L1. Plans; never executes.

🛠️ OpenCode L2 / L3

Capability-denied reviewer (edit/bash/network off, isolation-verified) and an approval-gated apply path: refused without owner approval, confined to a copy, sha256-verified to touch only declared files.

🔍 OpenClaw L0 · observe

Operationally read-only — it changes no authority, runs no tool, touches no sandbox. It reconciles the audit, metrics, isolation manifests, and policy across nine controls, then signs its own PASS/FAIL verdict into its assurance log under its own key. Append-only to its own evidence; still unable to act.

💬 Governed Chat Console /chat — operate

Drive that loop conversationally. Type a goal: Hermes plans at L1 and proposes a delegation — it executes nothing. You approve the sandbox apply; OpenCode applies and sub-delegates verification to OpenClaw; the attenuating chain, the verdict and the signed evidence lineage come back. Withhold approval and the apply refuses — the model proposes, only the person authorizes. It's the honest reading of "minimal human intervention": the human is out of typing every step, never out of holding authority. Run it from the repo checkout with private-ai-gateway demo, then open /chat. The UI serves from the package, but orchestration uses the bundled repo agents/ plane; outside the repo, set PRIVATE_AI_AGENTS_PATH or orchestration returns 503 orchestration_unavailable.

◧ Governance Console /console — inspect

The same runtime from the outside: connected identity and its enforced ceiling, the live decision audit, Prometheus-native counters, policy-rendered agent cards, declared tool floors, and a probe lab that sends real requests designed to be refused. The two pages link to each other but authenticate independently — no bearer token is shared, persisted, or handed between them, and the console is never a privileged bypass. Current build

From authority to trustworthy evidence

The loop proves authority; the current work hardens the evidence of what was authorized and what then happened — so a verdict no longer rests on artifacts the verified components wrote about themselves. Here is exactly where that stands, without overclaiming.

✅ Working now

  • Owner-gated execute loop — execute needs a durable, single-use, owner-approved decision bound to the plan's canonical hash; an inline approver grants nothing.
  • Three signed authority records — the gateway emits approval_decided (every owner decision) and execute_validated (authority granted, before any mutation); OpenCode emits a signed apply_result instead of leaving only a self-attested report.
  • Stable identity + signed linkage graph — every record carries an evidence_id and chain-independent digest, and the three records form a signed graph (approval_decided ← execute_validated ← apply_result) that OpenClaw re-derives and validates edge by edge, rejecting dangling, forged, cross-run, or ambiguous links.
  • Durable authority + evidence stores — runs, approvals, and the evidence chain persist as two separate, exclusively-owned, WAL-backed SQLite databases with fail-closed startup integrity: corruption, tampering, or a second concurrent owner fails at open, never silently.
  • Live durable evidence wiring — in the hardened configuration the whole loop lands in one durable signed chain: assurance-owned key custody, fail-closed emits (REQUIRE_AUTHORIZATION_EVIDENCE forced on), OpenClaw refusing a PASS without a verified signed chain, and the populated database re-verifying across restarts.
  • Append-first execution reservation — the durable execute_validated record is written before the single-use approval is consumed, so a crash in that window can no longer leave spent authority with no durable trace. Exactly one reservation can exist per approval, and one that outlives a crash is invalidated fail-closed at startup — nothing is retried, and another attempt needs fresh authority.
  • Startup cross-store reconciliation — one pass joins the authority store and the evidence chain at startup, after each independently validates itself, and classifies every approval before it acts. A run whose authority was consumed without a valid linked outcome is failed closed as dirty: invalidated and surfaced, never auto-retried and never claimed successful. Evidence with no matching authority never becomes authority, ambiguous evidence fails closed instead of being normalized, and a store that cannot be read aborts startup rather than reading as clean.
  • Reconciliation hardening — failing closed means acting: an inconsistency that can be tied to an extant authority run now invalidates that run, so an approval carrying incompatible or ambiguous execution evidence can never still execute. Only an orphan evidence fact with no matching authority run stays report-only. And “complete” is now exactly the verifier’s own full signed graph — apply → reservation → approval, with emitter identity, uniqueness, approve-decision and plan-hash agreement — never a weaker gateway-side check.
  • Signed verifier verdict — OpenClaw now signs its own PASS/FAIL with its own key and appends it to the chain it verifies, so the verdict is tamper-evident rather than hearsay. A signed PASS binds to the exact apply it judged and is unreachable over a broken authorization graph; if the verdict cannot be recorded, no verified state is advertised. The gateway never receives the verifier’s key.
  • Terminal run disposition — a human can finally finish a dirty run. The owner names one specific basis — a chosen signed verdict, or the exact reservation for a run where no verdict can legitimately exist — and the gateway re-resolves that reference, seals the run, and signs a terminal run_disposition. The honest default asserts nothing: closed_unknown records that the runtime cannot tell whether the mutation landed. Exactly one per run under concurrency; late evidence can never supersede it.
  • Reversibility foundation — the audit was negative: the shipped apply artifacts kept only changed paths, so nothing could be reversed, and hashes recorded after the fact never could be. A bounded, sandbox-confined pre-image is now captured before the first declared write — “did not exist” for a creation, prior bytes for an update or delete — and byte-exact restoration is proven by test. Contents stay on local disk; signed evidence carries only the snapshot’s identity and digest. A capture that cannot complete rejects the apply rather than quietly producing an irreversible one.
  • Governed rollback & containment — a sandbox apply can now be undone, and undoing is treated as what it is: a mutation. It gets its own governed run, its own single-use owner approval bound to a plan hash covering the exact apply and snapshot being reversed, its own reservation, and a signed outcome. A failure never becomes a success — the workspace is contained, marked for a human, and the rollback run is invalidated. OpenClaw re-reads the tree itself rather than trusting the executor’s claim. A success says only that the supported sandbox state was restored; nothing outside the sandbox is touched or claimed.
  • Trust history, read-only — a derived projection over the signed chain: verified completions, dirty executions, human closures, rollbacks and containments, keyed by principal and task class so success at documentation work never becomes trust for security work. Facts only — no score, no threshold, and nothing in the authorization path reads it: a flawless record leaves every ceiling exactly where it was. A chain that does not verify yields no ledger rather than an empty one. And an honest gap: no signed record names the model that served a run, so runtime history cannot yet be attributed to a model build.
  • Models & Routing console — a capability registry that answers four questions separately: what models exist (fingerprinted by build, not by config alias), which are usable on this host, which task lanes they have actually been measured on, and what authority the routed principals hold. Recommendations are deterministic and explainable — no model chooses the model — and a route change is a proposal: a browser dropdown never writes the policy file, and never alters autonomy, skills, tools or approval rights.
  • Local-model qualification — the local engineering model is now measured, not estimated. An 18-task corpus is graded by running each candidate in a disposable copy: 94% first-pass structural, 81% tests pass, 100% public API preserved, 72% zero-edit — and 0 of 14 on refusing control-weakening changes. Asked to delete a signature check, widen path confinement, return PASS when evidence is missing, or log the bearer token, it did all fourteen — each patch well-formed, in scope, and passing every structural check. That is why review is a control and not a courtesy, and why the model still holds no apply, commit, merge or deploy authority.

Honest limitations

The evidence chain is tamper-evident, not non-repudiation — a symmetric-HMAC MVP that detects tampering, reordering, and replay, but not a party holding an emitter's key (asymmetric keys / KMS are future). Autonomy is fixed-ceiling by policy: there is no self-approval and no earned-trust escalation, and execution stays human-gated in a confined sandbox. Runtime-wide crash-safe mutation semantics are still not claimed. An execution interrupted mid-flight is classified, failed closed, independently verified under a signed verdict, and can now be terminally closed by a human as unknown — but the runtime still cannot tell you whether that mutation actually landed. A future sandbox apply can be undone under owner authority; a historical one has no recorded pre-image and stays irreversible, and rollback never leaves the sandbox. This is a local-first, human-in-authority assurance and governance plane — not a fully autonomous, production-deployed, or compliance-certified system, and it has no users, revenue, or design partners. It is a working, tested, honestly-scoped engineering artifact.

Defense in depth

A STRIDE threat model that can't drift

Every mitigation cites the executable proof — an eval ID or unit test that runs in CI — so the threat model stays in lockstep with the code. Loopback → auth → authorization → egress: an attacker must cross every ring, each failing closed and each logged.
